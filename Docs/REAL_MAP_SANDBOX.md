# Real Map Sandbox

Status: new sandbox milestone (2026-08-02)
Runtime: Three.js r180, WebGL2, vendored `three-roads`, OpenStreetMap + DataSF data

## What it is

`/realmap.html` is a second playable surface in this repo: a low-poly San
Francisco sandbox built from the real city instead of the authored stylized
district. You draw a boundary over the real SF outline, then the lab generates
that slice as a 3D city with:

- the full SF shoreline/county boundary (24 DataSF rings, including islands);
- real OSM roads with lane-level surfaces, lane markings, curbs, and sidewalks
  generated by `three-roads`;
- OSM building footprints extruded with heights, plus city-wide block massing;
- real traffic-signal nodes rendered as animated signal heads using the shared
  signal timing from `src/signals.js`;
- one-way arrows and a small traffic simulation that respects one-way state and
  red-light stopping;
- clickable metadata for buildings, streets, and signals: OSM way ID, street
  name, highway class, one-way/two-way, lane count, speed limit, surface,
  sidewalk state, bridge/tunnel, building type, amenity, address, height,
  levels, and footprint area.

## Play

```bash
npm install
npm run build:realmap-assets   # regenerate the compact city asset (optional)
npm run dev
```

Open `http://localhost:5173/realmap.html`. Choose Draw and click to place
boundary vertices, double-click or press Enter to close the polygon, or use the
presets (Downtown, Mission, North Beach, Presidio, Outer Sunset, Full City).
Then press **Build 3D City**.

3D controls: drag to orbit, scroll to zoom, `W A S D` to pan, click a building,
street, or signal to inspect its OSM metadata, `H` to hide the HUD, **Back to
Map** to redraw another boundary.

## Data pipeline

1. `scripts/build-sf-atlas.mjs` parses the bbbike SF OSM PBF into `sf-atlas.json`
   (roads, building footprints, signals, boundary).
2. `scripts/build-realmap-assets.mjs` downloads the DataSF Shoreline and Islands
   GeoJSON (modifying view `txuc-3kzm`, PDDL 1.0), projects to local metres,
   clips roads/buildings/signals to the city boundary, and writes a compact
   flat-array `sf-city.json` plus a gzip variant.
3. The browser fetches `sf-city.json.gz`, decompresses with
   `DecompressionStream`, and builds only the roads/buildings inside the drawn
   polygon.

Attribution: `© OpenStreetMap contributors` (ODbL 1.0) and City and County of
San Francisco (DataSF PDDL 1.0). Source URLs and SHA-256 digests are stored in
`sf-city.json` metadata.

## Honest quality notes

This is a stylized low-poly sandbox, not a Schedule 1 / The Sims 4 clone. It
prioritizes real geography, metadata, and playable generation over AAA
character animation, interiors, or a fully streamed whole-city simulation.
Visual acceptance in this environment is enforced with quantitative render
gates (color variety, non-blank frames, draw calls, triangles) plus functional
checks, because the reviewing model cannot view screenshots directly. The
whole-city boundary is interactive via the Full City preset or a manual
polygon; generated road detail is richest in the OSM detail bbox and degrades
gracefully outside it.
